# zoomdoc プロダクト要件定義書

自律型AIコーディングエージェントのコンテキスト浪費と探索迷走を解決する、OKF型段階的開示インデックスプラグインの要件と受け入れ基準。

## 1. 背景・課題

自律型AIコーディングエージェント（Google Antigravity, Claude Code等）において、ドキュメント群（Living Specs, ADR, ガイドライン）を無差別に全走査（`grep`, `find`, ディレクトリ再帰読込）することによる以下の問題を解決する：

1. **コンテキストウィンドウの枯渇・浪費**: 本文全体を一度に読み込むことによるトークン消費の爆発。
2. **無関係なノイズ混入**: 別ドメインの仕様や古いドラフトがコンテキストに入り込み、ハルシネーションや指示違反を誘発。
3. **探索の非決定論性**: どこに必要な仕様があるか推測できず、探索試行回数が肥大化。

## 2. 対象ユーザーと利用シーン

- **AIコーディングエージェント**: タスク開始時の仕様把握、成果物作成時の格納先判定、実装完了時の整合性確認。
- **リポジトリ管理者・開発者**: リポジトリ内のドキュメントが常に最新（Current Truth）かつ規約通りに維持される状態の担保。

## 3. 機能要件

### 3.1 スキーマによる宣言と、確実な想起
- 残すべき文書（フォルダ、名前、書くとき、雛形）を `.zoomdoc/schema.yaml` で宣言できること。スキーマはフォルダのパスと説明（自然文）だけを持ち、決定論的に扱うのはパスだけとする。
- セッション開始時とスキーマ変更時に、スキーマをそのままコンテキストへ注入すること。エージェントは、ツールを呼ぶ前から、何をどこに残すかを知っていること。

### 3.2 段階的な探索
- 探索は、フォルダの役割（スキーマ）→ 各文書の `title` と `description`（本文を開かずに一覧）→ 必要な本文、の順で行えること。スキルが示す、範囲を絞ったコマンドで足りること。
- 専用のサーバー・索引・キャッシュを持たないこと。正本はファイルシステムだけとする。

### 3.3 ガバナンス・通知型ガードレール
作業を止めるブロックはせず、検知して通知する。
- セッション開始時（`SessionStart` / `PreInvocation`）に、各フォルダの起票トリガーをコンテキストへ注入すること。未初期化なら何も作らず `/zoomdoc:init` への誘導だけを出すこと。
- 未定義フォルダ・サブディレクトリ、Frontmatter（`title`, `description`）の欠損、リンク切れ、同じフォルダの title の重複、スキーマが参照する雛形の欠落を、プロンプト送信時のフックで検知して通知すること。直っていない指摘は、一定間隔で再通知すること。
- 説明に「確認してから」とあるフォルダは、エージェントがユーザーに確認してから書くこと（`zoomdoc:write` スキルの手順）。
- 欠落（`title` / `description`）は、フックが「あるべき状態と現状」の形で通知し、直すのはエージェントとすること。フックと `zoomdoc:lint` は文書を書き換えない。

## 4. 受け入れ基準

1. **トークン極小化**: セッション開始時の注入が数千トークン以内に収まり、変化が無い間は繰り返さないこと。
2. **全走査をしない**: エージェントが `find /` や再帰 `grep` を行わず、スキルが示すコマンドで目的の文書に到達できること。E2E（`tests/e2e/`）で測る。
3. **ゼロ依存実行**: フックは依存なしの Node.js スクリプト、移行と lint は単一バンドルで、`node_modules` なしで動くこと。
4. **ガードレール遵守**: 未定義パスへのファイル作成、Frontmatter 欠落、リンク切れが、次のプロンプトまでにフックで通知されること。
