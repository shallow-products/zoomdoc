# プラグイン・チューニング知見とエージェント制御ナレッジ

試行錯誤と実験から得られた、エージェントの行動最適化に関する実践知見。各項目に、**今も有効か**を添える。設計が変わって有効でなくなったものも、得られた理由ごと残す（同じ失敗を繰り返さないため）。

---

## 1. 施策とスコア変動の因果関係 (Optimization Log)

### ① PreInvocation によるトリガー事前注入の導入（有効）
- **施策**: セッション開始フック（現在は `sync-triggers.js`）で、`.zoomdoc/schema.yaml` の責務と起票トリガーをコンテキスト冒頭に自動注入。
- **効果**:
  - `Tool Precision`: **60% → 100% (+40pt)**
  - `Trajectory Efficiency`: **50% → 100% (+50pt)**
- **得られた知見**: エージェントは「ドキュメントの全体地図」を起動時に渡されると、手当たり次第に `grep` や `find` を叩く行動を完全に止め、必要なフォルダを絞って読み始める。

### ② ガードレール拒絶メッセージ（explanation）の簡潔化（教訓は有効、仕組みは廃止）
- **施策**: 当時の書き込み遮断フック（`guard-structure.js`。現在は廃止）の `deny` 理由を長文説教から「禁止事項（サブディレクトリ作成）＋許可されたフォルダ一覧」の2行に短縮。
- **効果**:
  - `Token Savings`: **85% → 92.3% (+7.3pt)**
  - リカバリー成功率: **100% 維持**
- **得られた知見**: エージェントに対するエラー通知は、長く理由を説明するよりも「何がダメで、どこなら良いか」を機械的に提示する方が、エージェントの自己修正が早く、トークン浪費も防げる。**遮断は廃止したが、この教訓は検知の通知文（あるべき状態・現状・根拠）に引き継いでいる。**

### ③ 実エージェントE2Eで見つけたこと(#47、#51。有効)
- **施策**: `tests/e2e/`で、実際のClaude Codeに、store/migrate/migrate-root/search/dedupeを複数回やらせ、ツール呼び出し・トークン・成否を集計した。スキーマは、構造化YAMLとMCPから、フォルダと自然文の説明だけの形に変えた。
- **効果**: store 10/10、dedupe 5/5、search 5/5、migrate 6/6。入力トークンはstoreで約15%、dedupeで約10%減った。
- **得られた知見**:
  - エージェントは、MCPより使い慣れたシェル(`ls`・`find`・`grep`)を選ぶ。MCPの専用ツールは、使われる前提にしない。
  - 「管理する文書はスキーマのフォルダにだけある」という約束は、スキルの一文より、Hookが注入する本文に書く方が効く。
  - 曖昧な文は読み違えられる(例: 「既存が連番なら合わせる」を、日付形式の場所に連番で作る根拠にした)。命名規則は、例外の条件まで書く。
  - 一覧の1行コマンド(`title`と`description`だけを出す)は、検索で約6割しか使われない。ファイル名で足りる場面では、使われない。多数の似た名前の文書がある場面は、未検証。
  - 評価の落とし穴: 利用上限に当たった実行は、0回の呼び出しで終わる。結果に混ぜない(`"You've hit your session limit"`を確認する)。確認待ちで止まる場面には、催促(nudge)を送る。
  - 正規表現による判定は、実行されなかったコマンド(`cat … || find …`)を数え違える。主張する前に、記録で確かめる。

## 2. エージェント制御の勝ちパターン (Best Practices)

1. **ツールの責務は単一に絞る**:
   - 詳細閲覧までこなす多機能ツールを作ると、エージェントが標準の `view_file` とどちらを使うべきか迷走する。目次の開示（`title` と `description` の一覧）と本文の閲覧は分ける。
2. **ルール（自然言語）だけに頼らず、フックで検知する**:
   - 「サブディレクトリを作るな」とルールに書くだけでは、エージェントが忘れて違反することがある。当時は `PreToolUse` の `deny` で物理的に遮断し、遵守率 100% を得た（**覆った知見**）。
   - その後、遮断は正当な作業まで止めて摩擦を生み、終了を止める仕組みは直せない指摘でループすると分かり、**遮断をやめて、検知と通知に切り替えた**（[hook-guardrails.md](../decisions/2026-10-07-hook-guardrails.md)）。遵守は、通知と再通知で見える状態を保つことで支える。
