# プラグイン評価設計と意思決定の軌跡

AIコーディングエージェント向けプラグインを正しく評価するために下した設計判断とアーキテクチャの変遷記録。

---

## 1. 評価アーキテクチャの二層分離 (ADR)

### 背景と課題
単体テストのみでは「実エージェントがプロンプトに対して自律的にツールを選んでくれるか」が検証できず、一方で実エージェントのテストのみでは「失敗がLLMの気まぐれかプログラムのバグか」の切り分けが困難であった。

### 決定内容
テストを **「静的E2E（配管テスト）」** と **「動的E2E（自律行動テスト）」** に二層分離した。

1. **静的E2E（決定論的検証）**:
   - フックと `doc_lint`、`init`、`migrate` のスクリプトを直接実行して、出力と副作用を検証する。
   - 目的: 通知の形、書き込まないこと、移行の結果が破綻なく動くことを数秒で保証。
2. **動的E2E（非決定論的検証）**:
   - `claude --plugin-dir . -p <prompt>` を非対話実行し、行動軌跡（Trajectory）と副作用を検証。
   - 目的: エージェントが迷走せず最短で目的を達成し、規約違反がフックで検知・通知されて直せることを確かめる。

---

## 2. 4大定量的メトリクスの選定理由

コミュニティおよび研究知見（NVIDIA NeMo, SWE-bench, DeepEval 等）を基に、以下の4指標を公式採用した：

1. **Tool Precision**: 当てずっぽうな探索（grep乱発）をペナルティ化し、目次参照へ誘導できているかを測定。
2. **Trajectory Efficiency**: 最短ステップ数に対する実ステップ数の比率により、エージェントの思考迷走を検知。
3. **Token Savings**: OKF型段階的開示がコンテキストウィンドウをどれだけ節約できたかを定量的数値化。
4. **Compliance Rate**: 悪問（Adversarial）に対して、規約違反が検知・通知され、エージェントが正しい状態に直せた割合。測定時点（v0.3.0 まで）の定義は、物理防御（遮断）の成功率だった。

---

## 3. テストハーネスのサブスクリプション活用設計

外部評価SaaSやライブラリ（DeepEval等）は従量課金APIキーが必要となる。
本プロジェクトでは、Claude Code CLI の `--print --output-format json` をテストランナー（Vitest）から呼ぶ設計を採用し、**追加課金ゼロ（既存の月額サブスクリプション枠）** かつ **45秒強制タイムアウト（Wall-clock Guardrail）** による暴走遮断を実現した。
