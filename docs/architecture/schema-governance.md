# スキーマ＆ガバナンス定義仕様

リポジトリ全体のドキュメント配置責務と行動規律を統括する `.zoomdoc/schema.yaml` の記法・ガバナンス設計。

## 1. 必須フィールド（全ドキュメント共通）

すべてのドキュメントは以下の2項目を Frontmatter に持つことがシステム上必須。どちらも、本文を開かずに内容を一覧するための情報：
* `title`: ドキュメントの正式名称
* `description`: 1〜2行の要約

作成日・更新日は書かない。必要なときは git の履歴から求める。手で書くと更新を忘れて嘘になるため。

## 2. スキーマの形

`.zoomdoc/schema.yaml` は、**フォルダのパス（キー）と、そのフォルダの `description`、置く文書の行（`documents`）** を持つ。サブディレクトリの新設は一律禁止で、`folders` に書かれたパスだけを許可する。

* **決定論的に扱うもの**: フォルダのパス（ディレクトリ名）と、文書の行の必須の欄が埋まっているか。パスは、未許可フォルダの検査、サブディレクトリの検出、ルートの導出に使う。
* **文書の行（`documents`）**: `name`（ファイル名または名前の規則）・`description`・`create`（いつ作るか）・`update`（いつ更新するか。更新しないなら「更新しない」）が必須。`template`（雛形のパス全体）と `remove`（削除・移動の条件。省略時は承認なしに削除・移動しない）は任意。`documents` が無いフォルダは、`description` だけの従来の書き方で動く。
* **自然文で書くもの**: 欄の値はすべて自然文で、エージェントが読んで従う。名前の規則の書き方は定義しない（固定名か規則かは、エージェントが読んで判断する）。機械は値の内容の合否を判定しない。必須の欄の欠落と、雛形のパスの実在は `zoomdoc:lint` が確かめる。
* **共通の書き方**（Frontmatter・日付・サブディレクトリ・1概念1ファイル）: スキーマではなく `zoomdoc:write` スキルが持つ。文書ごとの例外は、その行に書く。
* **ドキュメントのルート**: 既定は `docs`。専用の設定は持たず、`folders` のキーの共通の親がルートになる。`/zoomdoc:init` が最初に尋ね、ほかの名前ならキーをそのパス配下にして配備する。フォルダが複数のルートに散らばると決まらず、`zoomdoc:lint` とフック（`detect-issues`）が警告する。
* **Frontmatter の2項目**（`title` / `description`）は、例外的に決定論的で、`zoomdoc:lint` とフックが検査する。
* **雛形である**: 同梱のスキーマとテンプレートは出発点で、ユーザーが自分の運用に合わせて変えていく。
* **機械は書き込まない**: フックと `zoomdoc:lint` は、`schema.yaml` も文書も書き換えない（検知と通知だけ）。直すのは通知を受けたエージェントで、機械が書き込むのは、ユーザーが承認した移行の `apply` だけ。
* **スキーマの変更権限**: フォルダの追加や説明の変更は、移行時はユーザーがプランを選択・承認した後に限る。承認前は `migrate plan` が出す食い違い（`schemaGaps`）の提示にとどめる。
* **書き方の注意**: 迷いやすい決まりは、条件を明確に書く。曖昧な括弧書き（例:「既存が連番ならそれに合わせる」）は、読み違えられることがある。
* **スキーマの大きさ**: スキーマは毎セッション、そのまま文脈に入る。上限は設けず、READMEで利用者に注意する。

## 3. ガバナンス判定の流れ

1. **常時認知**: セッション開始時とスキーマ変更時に、フックがスキーマをそのまま（コメントと空行を除いて）注入する。要約はしない。エージェントは、ツールを呼ぶ前から、何がどこにあり、いつ書くかを知っている。
2. **執筆準備**: フォルダの説明と文書の行から置き場を選び、行の `name` と `template` に従う。雛形は書く前に読む。具体的なファイル名の行はそのファイルの有無で、名前の規則の行はフォルダの既存文書の `title` と `description` を一覧して、新規か更新かを決める。`update` が「更新しない」の文書は、追記せず新しく作る。
3. **確認**: 説明に「確認してから」とあるフォルダへ書く前に、エージェントがユーザーに確認する（`zoomdoc:write` スキルの手順）。
4. **フォルダの役割**: フォルダの `description` が持つ。フォルダ直下に `description.md` は置かない。
