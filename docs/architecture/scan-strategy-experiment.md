# スキャン抽出戦略の比較実験

`/zoomdoc:init` のスキャンは、各ファイルの抜粋だけをLLMに渡す。抜粋を減らすほど安いが、末尾の注記などを見落とす。何をどれだけ渡すのが妥当かを実測した。

## 結論

- **既定は `head30-tail10`**（先頭30行＋末尾10行）。最高精度（95.8%）で、約590トークン/件。
- **末尾を含めること自体が要**。先頭だけ・見出しだけの戦略は、末尾にだけ書かれた「廃止」注記を3件とも見落とした（`head5`・`headings`・`headings-lead5` は0/3）。
- **全文は割に合わない**。`full` は837トークン/件で91.7%と、`head30-tail10` より高くも安くもない。
- **大規模（80件超）では `pct20-10`**（先頭20%＋末尾10%）。約250トークン/件で91.7%。差は1件分で、誤差の範囲。この閾値（80件）は実験の規模（24件）からの外挿。
- 勧める戦略は `migrate scan` の `recommendedStrategy` に理由つきで出る。

## 結果（Markdown 24件）

| 戦略 | トークン/件（概算） | 正解率 | 廃止注記（末尾のみ） |
|:---|---:|---:|:---:|
| `head5` | 63 | 70.8% | 0/3 |
| `headings` | 60 | 79.2% | 0/3 |
| `headings-lead5` | 107 | 75.0% | 0/3 |
| `pct20-10` | 254 | 91.7% | 3/3 |
| `head15-tail5` | 332 | 87.5% | 3/3 |
| **`head30-tail10`** | **588** | **95.8%** | 3/3 |
| `head50-tail20` | 742 | 95.8% | 3/3 |
| `full` | 837 | 91.7% | 3/3 |

費用対効果の境界線（他に勝たれる戦略を除いたもの）は `head5` → `pct20-10` → `head30-tail10`。`head15-tail5` は `pct20-10` より高く精度が低い。`head50-tail20` と `full` は `head30-tail10` に勝てない。

## 非Markdown形式（10件）

`.txt` / `.rst` / `.adoc` / OpenAPI `.yaml` / AsyncAPI `.json` を、汎用の行スライスと形式を考慮した抜粋（仕様は題名・説明・操作の一覧）で比べた。**どちらも100%で差は出なかった**（386 → 361トークン/件）。コーパスが易しく、形式対応の効果は実測できていない。仕様ファイルは行数が多くなりやすいので、トークン節約として形式対応を既定で有効にしている。

## 条件と限界

- **モデル**: Claude Haiku。**1戦略につき1回**。1件の違いが約4ポイントなので、数ポイント差は誤差。
- **コーパス**: このリポジトリの `docs/`（21件、正解＝置かれているフォルダ）に、長い文書の末尾へ廃止注記を足した3件を加えたもの。ファイル名は伏せ、Frontmatterは除いた。件数が少なく、実際の移行対象より整っている。
- **誤りの原因**: `head30-tail10` の唯一の誤り（architecture → evaluation）はベンチマーク文書で、フォルダの選び方自体が曖昧。抜粋の量では解決しない。
- 推定トークンは文字数からの概算（ASCII約4文字/token、日本語約1.5文字/token）で、実トークナイザの値ではない。

## 再現

```bash
node scripts/scan_experiment.js prepare --out <dir>   # 戦略ごとの分類プロンプトを作る
# <dir>/prompts/<名前>.md をモデルに渡し、返ってきたJSONを <dir>/responses/<名前>.json に保存
node scripts/scan_experiment.js score --out <dir>     # 表にする
```

コーパスと抜粋の実装は `src/migration/experiment.ts` と `src/migration/extractors.ts`、非Markdownの試料は `tests/fixtures/scan-formats/`。
